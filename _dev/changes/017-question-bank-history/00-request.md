## 用户目标

1. “清空本段”成功后，桌面实时答案历史回到干净待记录状态；题库原始记录、截图和模型上下文继续保留。
2. 最近历史分段可点击，只读查看该段的提交、截图、完整原答案和已有整理题目。浏览历史不得切换后台当前段，也不得写入实时 `solution.history`。
3. 界面严格只显示最近 20 个分段。更早分段只隐藏，继续保留在 `_记录` 和已有导出目录中，不自动导出、不调用模型、不删除文件。
4. 使用招聘单位、出题方和题型形成稳定名称。模型只在用户显式启用整理时复用现有请求生成候选，不增加请求次数；候选必须人工核对后才能成为权威元数据。

## 用户已确认的方案

- 元数据识别采用“复用模型整理”：不开启整理时不调用模型；开启时从原有逐 Record 请求一并返回候选。
- 超出最近 20 段采用“仅隐藏并保留”：不自动导出、不自动整理、不删除。
- 启用模型整理时采用两阶段流程：“整理并生成建议”后由用户核对，再执行纯本地最终导出。

## 非目标

- 不恢复历史段为当前可写 Session，不用 `Store.Open` 预览。
- 不截断 `Store.List()` 的全量语义。
- 不建立多级物理分类目录，不移动旧 `_记录`、截图或导出目录。
- 不清空 Solver 模型上下文、后端截图缓冲或 Mobile 显示。
- 不新增依赖、不升级 Wails runtime。
- 本 Change 不执行 commit、push、Tag 或 Release。

## 验收标准

- 清空成功才重置桌面实时历史；取消或失败保持原状。
- 最近 20 段可只读浏览；`discarded` 可查看但不可恢复、整理或导出；第 21 段不在 UI API 中开放。
- 历史详情不改变 current、Session/Record 状态或磁盘文件；DTO 不泄露磁盘路径。
- 图片按 ID 与索引安全读取，拒绝路径穿越、符号链接、非法格式、超限文件与超限像素。
- 模型候选不自动覆盖权威字段；最终确认后才持久化并导出，且不发生第二轮模型调用。
- Change 016 的固定链接、清屏确认和快捷键行为不回退。
