# Change 024 变更请求：题库整理失败恢复

日期：2026-10-25
状态：计划已批准，事前治理进行中；未经授权不提交、不推送、不发布。

## 背景

TCL 综合笔试最近一次导出生成了题目数量为 0 的整理稿。原 Session `a6ef78f5c602e1950b991e3d` 的 25 条完整答案、结构化答案摘要和 25 张截图仍完整保留，但 25 条二次题库整理均失败。当前程序把 `pending == 0` 当作“准备完成”，导致全部失败也能进入最终本地导出并写出空整理稿。

现有 Session 只保存统一文案“整理失败，请重试或查看原稿”，无法证明本次是请求、超时、空响应、JSON、schema、来源映射或 provider 兼容中的哪一种失败。本 Change 不伪造底层根因。

## 目标

- 区分 pending、complete、partial、all_failed、no_eligible。
- 全部失败时禁止零题整理稿，只允许显式重试失败项或仅导出原稿。
- 部分失败时显示成功、失败和题目数，并允许重试失败项、明确导出已有结果或仅导出原稿。
- 保存受限、脱敏的失败分类；成功重试后清除失败标记。
- 保留两阶段流程：准备整理后人工核对，最终确认只执行本地导出。
- 保留成功项，失败重试不重复调用成功项。
- 保留当前弹窗的 `autoOrganize` 选择，不修改长期偏好。
- 创建 `2026-10-25_095652_TCL_综合笔试_02` 离线恢复稿，不覆盖旧导出或回写 Session。

## 验收标准

- 全失败不得显示“准备完成”，不得创建零题整理稿或 ExportSnapshot。
- RawOnly 始终可生成 `原始记录.md` 和 `assets/`。
- 部分导出必须由 UI 明确选择；最终确认零 provider 调用。
- 失败信息不包含密钥、Token、Header、完整 URL、绝对路径、原始错误体、Prompt、Base64 或完整模型响应。
- `_02` 恢复稿前半试题、后半参考答案与解析；27 个推定题位均有来源或缺失说明。
- 原目录、`_记录`、截图、原答案和旧导出哈希保持不变。

## 非目标

- 不调用真实模型验证，不消费真实 API 额度。
- 不断言某一 provider 或模型是确定根因。
- 不增加隐藏自动重试、并发整理或第二次模型调用。
- 不宽泛提取 prose 中的 JSON，不修补来源 ID 或图片索引。
- 不新增依赖、不升级 Wails runtime、不修改用户 API/快捷键配置。
- 不覆盖正式程序或旧验证程序。
