### 3.2 使用流程与范围

1. 用户点击“开始本场”，输入单位/题型，选择或确认输出根目录。
2. 本场每次提交自动保存所有截图与对应答案，界面显示当前场次、记录数量和保存状态。
3. 用户点击“结束并导出”，由后端确认无未完成解题任务后封存场次，先导出本地原稿。
4. 用户确认结构化整理：界面提示会把本场截图、答案发送到当前配置的服务商，会产生额外调用；显示进度并支持取消。
5. 生成完整题库并显示保存位置；失败/取消时明确说明哪些整理完成、哪些待重试，原稿不受影响。

约定：
- 不自动识别考试网页的“结束”动作；结束本场是显式操作。
- 未开始场次时，原有解题功能照常工作，界面明确显示“未录制”；不能事后恢复从未保存或已经丢失的历史题目。
- “一次提交”是原始记录单位：1～3 张图可属于同一道题，也可能包含多题。原稿按提交顺序保留；整理结果可拆成多道题，但每题必须回链原始记录及截图。
- 清理桌面历史、切换 `KeepContext`、更换输出模式，不删除本场记录。
- 不修改现有 PNG 导出行为，不开发手机端导出界面，不增加网申业务，不增加自动场景切换。

### 3.3 数据层：新增独立题库模块

新增 `pkg/questionbank/`，按职责拆为数据结构、场次存储、Markdown 导出、模型整理四部分，全部使用现有依赖与 Go 标准库，不新增数据库或 SDK。

数据至少包含：
- 场次：稳定 ID、单位、题型、开始/结束时间、状态、记录顺序、格式版本。
- 提交记录：稳定 ID、顺序、提交时间、全部截图相对路径、请求时的模型与场景标识、原答案、完成状态。
- 状态区分：处理中、完成、失败、已取消、异常中断/答案缺失；未完成内容不伪装为完整答案。
- 整理结果独立保存：文字题干、选项（如有）、题型、知识点、解题要点、来源记录、待核对说明。不覆盖原答案。

可靠性要求：
- 提交时复制截图和请求配置快照；写入截图后记录场次，再调用解题服务。归档失败必须明确告警，不能显示“已保存”。
- 成功终态以 `solution` 的完整内容为准，而非浏览器分片拼接结果；流式正文用于取消/失败后的部分记录，不保存模型内部思考过程。
- 按记录 ID 捕获回调，避免取消后旧任务的迟到回调串到下一题。场次关闭、导出、写入之间有互斥与状态校验。
- 原稿逐条落盘，文件更新采用同目录临时文件与可靠替换；启动后可识别未结束场次，并提供继续或封存操作，不依赖前端内存恢复。
- 磁盘错误时保留可恢复的内存结果并允许重试；关闭前提示仍有未保存记录，不宣称绝对防丢。
- 仅保存必要元数据；不序列化整个 Config，不保存 API Key、Token、BaseURL 查询参数、简历或带凭据的原始错误。

### 3.4 接入点与复用

- 修改 `app/app.go`：装配题库服务，关闭时收敛本次新增的归档/整理任务。
- 修改 `app/solve.go`：在已有截图复制和 `solveInternal` 编排点建立记录；包装现有 `solution.Callbacks.EmitEvent`，先更新对应记录，再透传 `a.EmitEvent`。
- 不从 `chatHistory` 取数据，不改变现有解题事件名或 mobile/dual 路由协议；尽量不修改 Solver 的解题逻辑。
- 新增 `app/questionbank.go`：场次开始/状态/恢复/结束、选择目录、导出/整理/取消整理等 Wails 接口；用独立整理 context，不复用 `CancelRunningTask`，避免取消正常解题。
- 新增前端 `stores/questionbank.js`、`components/QuestionBankPanel.vue`，在 `App.vue`、`TopBar.vue` 提供全局入口，手机独占模式恢复桌面后也能访问。

可复用组件/接口：

### 3.5 输出目录与配置边界

- 首次开始场次时通过目录对话框确认输出根目录，本工作区预期选择 `E:\DATA\求职_AI\输出`；代码不硬编码本机绝对路径。
- 只保存导出偏好到独立的用户级 `Q-Solver/questionbank-settings.json`，仅含输出路径/格式版本，由用户在应用中选择目录时写入。开发过程不直接写用户偏好文件。
- 原有加密配置文件、`config/`、`.env` 和 agentmemory 配置均不修改；目录迁移也不批量替换个人配置路径。
- 已配置输出目录不存在或不可写时，明确报错并允许重选，不悄悄把敏感输出写进源码目录。

### 3.6 结构化整理与导出

- 原始导出不需要联网；本地原稿先成功落盘，再启动额外模型整理。
- 整理使用单独的请求与配置快照，复用现有 OpenAI-compatible provider，不携带 Solver 上下文、简历或角色提示词；不改变当前解题场景。
- 按提交记录顺序逐条处理，限制单次输入规模，显示进度；仅重试失败项，不把整场截图塞入一次超大请求。
- 模型返回结构化 JSON，由应用校验字段、长度、题目列表与来源映射，Markdown 由本地模板生成。不能让模型决定文件路径或创建任意链接。
- 对模糊图像、缺失题干、原答案与题意不符等，标为“待核对”，不得补造题目或将模型答案称为官方标准答案。
- 原始答案逐字保留；提炼出的解题要点与原始内容区分展示。不自动去重或丢弃重复提交。
- PNG/JPEG 按真实格式落盘；名称防止路径穿越、Windows 保留名、非法字符、尾随点/空格、空名称和过长路径。
- 新导出目录先写入临时目录，文件齐备后再交付最终目录；重复导出不覆盖旧文件。相对图片路径保证整个文件夹搬移后仍可阅读。
- 题库 Markdown 包含元信息、目录、分类题目、截图、文字题干、原答案引用、知识点/要点及核对提示；失败、取消和中断记录在原稿中完整列出。

## 验证与回退


### 自动化测试（先用 fake provider，不调用用户真实模型）

- 多场次隔离、开始/结束边界、记录顺序、重复结束/导出。
- 一次 1～3 张截图全部保存，PNG/JPEG 格式正确；超过 10 轮、KeepContext 开/关、前端删除历史均不影响归档。
- desktop/mobile/dual 下记录一致，且不改变现有事件路由。
- 完整答案优先于分片；失败、取消、空答案、取消后迟到回调、处理中关闭场次不串题。
- 重启识别未结束场次，损坏记录可诊断，写入失败有反馈；临时目录或 JSON 文件损坏不得被标为成功。
- 中文与 Windows 非法文件名、目录穿越、同名导出、不存在/不可写输出目录、跨文件夹搬移后的相对图片链接。
- 整理 mock 覆盖成功、多题拆分、无效 JSON、缺失字段、错误来源映射、超时/取消、部分失败、只重试失败记录；原始截图和答案在所有分支保持不变。
- 归档与整理 payload 不携带密钥、简历、系统配置或 KeepContext 历史。
