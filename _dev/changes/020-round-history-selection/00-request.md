# Change 020 请求

日期：2026-10-23
状态：方案已批准，事前归档进行中；未提交、未推送、未发布。

## 用户请求

主截图解题界面的历史记录应按每次提交分别显示，而不是把同一分段中的多轮答案聚合在一条左侧记录里并在右侧连续展示。点击某条历史记录后，右侧只显示该轮截图、思考过程、答案和错误状态。

## 目标

1. 每个 Session/分段内的每个 Record/轮次在左侧成为独立历史条目，最新轮优先。
2. 点击任意条目后，右侧只显示该轮，不再连续渲染同 Session 的其他轮。
3. 新请求开始时自动选中新 Record；用户浏览旧轮时，后台当前轮仍按 `epoch + sessionId + recordId` 正确更新。
4. 题库续接恢复全部 Records，左侧逐轮显示并默认选中最新 Record。
5. 保留 Session 作为题库续接、模型上下文、导出和删除的权威边界。
6. 保留 Change 019 的截图折叠、按需加载、缓存与迟到响应保护。

## 验收标准

- [ ] 连续提交两轮后，左侧出现两条独立记录，最新一轮在上，不显示“2 轮”等聚合徽标。
- [ ] 每条摘要来自自身答案；点击任一条后右侧只显示该轮。
- [ ] 新 `request-start` 自动选中新 Record；同 Session 的旧轮不显示新轮 loading、thinking 或 streaming cursor。
- [ ] 浏览旧轮或只读 Session 时，后台流仍只写真实目标 Record，答案不串轮。
- [ ] 题库续接后全部 Records 都成为历史条目，默认选中最后一条 Record。
- [ ] 删除或导出菜单明确为父 Session/会话级操作，不伪装成单 Record 持久化能力。
- [ ] 删除 Session、软清空或重置后，浏览目标和流目标不悬挂；迟到图片响应不回写。
- [ ] 前端专项回归、既有题库/Mobile 回归、Vite、Go 普通验证和独立 Wails 构建按真实结果记录。

## 非目标

- 不物理扁平化题库 Session/Record 或 Pinia 的 `history[] -> rounds[]` 权威结构。
- 不新增单 Record 持久化删除、单轮题库导出或从任意 Record 截断并恢复模型上下文。
- 不修改 Go 后端、Wails API/bindings、Mobile 协议、模型请求、题库 schema 或依赖。
- 不删除、覆盖或迁移题库原始记录、截图、旧导出和旧验证程序。
