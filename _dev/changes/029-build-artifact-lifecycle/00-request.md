# Change 029：请求

## 用户目标

整理 `build/bin/` 的构建产物，使目录职责稳定、可审计且便于后续持续执行：

1. `build/bin/` 根目录只显示最终可运行版本 `Q-Solver.exe`；
2. 历史验证 EXE、旧稳定版、开发产物和临时备份按用途归档；
3. 每次候选测试期间，测试前稳定版与最新候选版允许共处于明确的 `testing/current/` 路径；
4. 测试通过后，将测试文件归档并把候选晋升为根目录最终版；测试失败时不得改变根目录稳定版；
5. 将上述生命周期、哈希校验、回滚和 Git/Release 边界写入项目规则；
6. 完成验证和提交边界审计后，将批准范围内的 Change 024～031 整合提交并推送到 `origin/dev/qsolver-custom`。

## 已确认选择

- 根目录最终只保留 `Q-Solver.exe`。
- 测试中的稳定版与候选版统一放在 `build/bin/testing/current/`。
- 归档按 Change 编号组织，并维护 SHA-256 清单。
- Change 024～031 采用一次性跨 Change 整合例外：功能/测试与治理/审计分为两个实施提交。
- 连同本 Change 的设计提交，本轮共计划三个提交。
- 仅允许推送 `origin/dev/qsolver-custom`；不推送 `upstream`，不修改 `main`，不 force push，不创建 Tag、GitHub Release 或新的 RC。

## 成功标准

- 根目录最终仅有一个 EXE：`build/bin/Q-Solver.exe`。
- 最终 EXE 来自通过完整验证的最新候选，具备可复核 SHA-256。
- 旧产物均有明确归属；不存在无说明删除或覆盖。
- 测试前、测试中、通过、失败和回滚路径均有确定操作顺序。
- Git 提交不包含被忽略的二进制、用户配置、CCR 配置/数据库/日志、仓库外探针或任何凭据。
- 三个提交的内容边界可审计，最终仅推送到已授权远端分支。

## 当前阶段边界

本文件与 `01-current-state.md`、`design.md` 构成事前设计。设计提交阶段不移动 EXE、不修改项目规则、不构建候选、不暂存 Change 024～031 的实现，也不执行 push。
