# 06 — 产品决策问题（Mobile Output User Decisions）

> 只读设计审计。本节**仅整理** Mobile Output 需要产品/负责人拍板的**非技术**决策。
> ⚠️ **本审计不做选择**——每条列出问题与依据（源码/实测证据），供用户逐条确认。
> 技术候选比较见 02/04，这里只聚焦「要做什么产品」。

---

### D-Mobile-001 手机端形态

**问题**：手机端用什么打开？
- a) 浏览器 Web 页面（扫二维码直接开 SPA）
- b) 小程序 / App（需要开发 + 发布，侵入高）

**Observed**：项目当前纯本地 Wails 桌面（无多端基建），浏览器方案零上线门槛。考试场景用户最快的动作是「扫码 → 浏览器查看」。

---

### D-Mobile-002 网络范围

**问题**：手机端连接范围是？
- a) **局域网（LAN only）** —— 手机与电脑同一 Wi-Fi；无公网暴露，本地优先
- b) 公网可达（云中继/内网穿透）—— 需外部服务，与「本地优先 + 隐私（截图含题面/简历）」冲突
- **Observed**：架构审计结论「本地优先」，且简历/题面属敏感内容（F-013）。建议 a，但不替用户决定。

---

### D-Mobile-003 手机显示内容粒度

**问题**：手机端展示到什么程度？
- a) 仅最终答案（静态）
- b) 答案 + 简单解析（摘要）
- c) 完整流程（思考链 + 流式正文 + 最终答案）

**说明**：选择 a/b → 传输可用简单轮询（02 方案 B），c → 必须流式（WS/SSE）。且影响 03 数据结构（payload 全量 vs 增量）。**直接决定第 8/14 部分方案收敛方向**。

---

### D-Mobile-004 电脑端行为（OutputMode 语义）

**问题**：手机显示时，桌面窗口如何处理？
- a) 桌面**隐藏**答案/渲染（仅手机看，Ghost 模式配合）→ `outputMode: mobile`
- b) 桌面**同步显示**（双端都看）→ `outputMode: dual/both`
- c) 桌面可**一键切换**（按钮切模式）
- d) 桌面永远正常显示（手机仅是额外镜像）

**Observed**：桌面是幽灵隐身窗口（main.go:38-47 透明 + `websocket transparent`）——隐身 + 手机输出叠加是产品特色场景，用户决定哪种是「主力观看屏」。

---

### D-Mobile-005 连接方式

**问题**：手机如何发现并连上桌面？
- A) **二维码扫码**（桌面显示二维码，手机识别连）
- B) 手动输入 `IP:端口`（可靠性兜底）
- C) 两者兼顾（二维码为主 + 手动兜底）

**考虑**：二维码主流程最顺考试场景；但二维码需要桌面在可扫位置（幽灵窗口时可能不可见）。**可备注连接开关是否常显**。

---

### D-Mobile-006 手机是否可控制桌

**问题**：手机端是「只读看答案」，还是「看 + 控制」？
- A) 只读（SSE 单向就够）
- B) 只读 + 断线重连（SSE + EventSource 天然支持）
- C) 可反控（停止 / 重新解题 / 切换场景）→ 需要双向通道（WS 或 SSE+POST）

**Observed**：A/B 复验成本最低、最贴「第二输出」定位（「核心变化只是输出位置」）。C 会显著扩大传输复杂度与安全性需审计。

## 附 A — 与审计 001 关键 Finding 的关联（第十六部分）

| Finding | 与 Mobile Output 关系 | 处理建议 |
|---|---|---|
| **F-001 KeepContext 后端无效** | 强相关：Mobile 若显示「多轮 rounds」，当前每轮独立（后端不携带历史）；且若未来修真多轮，`rounds` 语义会变（03 已预留 `rounds` 字段） | **建议独立处理 / 先定 Mobile 是否基于「当前单轮」**；修复 F-001 可另件进行 |
| **F-002 solve 快捷键未绑定** | 间接：移动端连接后，桌面无 `solve` 快捷键不阻碍手机「看」；手机端若想「一键触发解题」需依赖 F-002 就绪 | 独立分析 f。手机反向控制（D-Mobile-006 C）依赖触发链已有快捷入口 |
| **F-004 Windows 置顶不可控** | 弱相关：置顶开关仅影响桌面窗口层；Mobile 输出的本质是「桌面窗口外显示」。但置顶不可控 = 桌面不可藏，可能影响「手机为主 mode」的隐身体验 | 建议独立处理 |

> **结论**：Mobile Output 与三个 F **无必须同时修复的强耦合**。F-002 仅在「手机反向触发」option 才相关，F-004 影响体验但不阻塞；F-001 若目标是「手机看多轮历史」才需前置。三者均建议按各自时序开发，Mobile Output 可独立启谱。
