# 总结与注意事项 06

## 变更摘要

Change 013 将题库导出从“点击即执行”改为“先确认、再提交”的单例弹窗流程。设置页只保存默认目录与默认整理开关；单位、题型、题库名称、一次性目录和本次模型授权都在每次导出时确认。当前段与历史段共用同一窗口，历史重导出不会切换当前可写分段。

输出契约同步收敛：`原始记录.md` 与 `assets/` 始终保留全部截图和完整原答案；启用模型整理时额外生成以题库名称命名的无图试卷，前半为试题，后半为参考答案与解析。关闭整理时不再生成误导性的空试卷。导出与结束分段后，下一次解题自动懒建新段。

## 经验与踩坑

| 现象/坑 | 原因 | 结论/建议 |
|---|---|---|
| Wails `-clean` 构建在最后阶段失败 | 旧 `build/bin/Q-Solver.exe` 被运行中的进程占用 | 不强杀用户进程；改用独立 `-o` 输出名验证生产构建。 |
| Wails CLI 2.16.0 改写 runtime shim | CLI 高于项目 runtime 2.11.0，生成了项目当前版本不需要的通知 API | 正式 App bindings 与 runtime shim 分开审查；保留业务 bindings，定向恢复 runtime 和依赖噪音。 |
| `-skipbindings` 后 runtime shim 仍被重写 | Wails 的前端构建步骤仍会同步 runtime 文件 | 生产构建完成后必须再次做差异检查，不能仅凭参数假定文件未变。 |
| 关闭模型整理的旧测试仍断言存在 `题库.md` | 旧兼容语义与本次批准的“仅原稿”语义冲突 | 测试应检查 `RawMarkdown` 存在且 `Markdown` 为空。 |
| 在多层 Bash/Python 字符串中插入 Go 换行转义导致语法错误 | `\n` 被中间层展开为实际换行 | 对生成代码避免脆弱的多层转义；本次用 `%c` 写换行，并立即执行 `gofmt` 与聚焦测试。 |
| 原答案直接写入 Markdown 存在 HTML/外链活动内容风险 | “逐字保留”不等于“直接作为 Markdown 解释” | 使用长于答案内部最长反引号序列的围栏，既保留原文又中和活动渲染。 |
| 一次提交不等于一道题 | 1～3 张截图可能含一题或多题 | 所有 UI 统一使用“次提交”，题目数量只在整理结果中单独展示。 |

## 对本项目后续的影响

- 题库长期偏好现在只包含默认目录和默认整理开关；旧 `company` 字段保留兼容但不再生效。
- 新导出 API 的 Promise 只表示后台任务已接受；前端必须继续依赖 `question-bank-updated`、状态消息和 `lastExport` 判断最终结果。
- `QuestionBankStatus.Operation` 区分 `exporting` 与 `organizing`，便于前端准确描述本地导出和模型整理。
- 导出弹窗是 App 根级单例；新增其他入口时应调用 Store 的 `openExport`，不要复制第二套弹窗或先切换 Session。
- 输出目录与恢复目录保持解耦：一次性目录只影响最终导出，`_记录` 始终留在默认题库根目录。
- 每次导出创建新版本目录，不覆盖旧输出；软清空也不物理删除恢复文件。

## 遗留项与 TODO

- `NEEDS_USER`：Windows WebView2 人工验证弹窗焦点、滚动、窄屏布局和目录选择器。
- `NEEDS_USER`：用户自愿开启后验证一次真实模型整理；开发验证不得代替授权或消费 API 额度。
- `BLOCKED`：Windows race 运行受 `0xc0000139` 阻塞。
- 后续可独立处理：统一旧 `OrganizeQuestionBank` 状态机、改用统一 provider 获取、坏 Session 隔离、名称清理规则统一，以及大图/长答案场景的 I/O 与内存优化。
- 前端主 chunk 仍为 814.31 kB；如要拆包，应作为独立性能 Change，不与本次 UX 收尾混合。
