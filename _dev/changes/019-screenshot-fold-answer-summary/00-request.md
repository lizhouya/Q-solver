# Change 019 请求

日期：2026-10-23
状态：方案已确认，事前归档完成后进入实现；未提交、未推送、未发布。

## 用户请求

优化截图解题主界面的图片显示和模型角色设定：截图默认保持紧凑，点击后显示，再次点击按钮或图片继续隐藏；当一次提交的多张截图共同包含多道题时，模型需要完整识别并逐题作答，最后汇总各题答案，例如五道选择题给出便于快速查看的选项汇总。

## 目标

1. 当前轮和历史轮的每张截图独立、默认收起，并提供明确的“显示截图（N）/隐藏截图（N）”操作。
2. 历史截图仍按需安全读取；收起不清理缓存、导出兼容字段或题库文件。
3. 多张截图作为同一批输入识别：跨图同题合并，重叠内容去重，全部题目按原题号或出现顺序逐题作答。
4. 本轮存在两道及以上待解原题时，在正文末尾增加“最终答案汇总”；选择题汇总选项，其他题型汇总结果或结论。
5. 信息不完整或无法可靠辨认时标记“待核对”，不猜测题干、选项或答案。

## 验收标准

- [ ] 当前轮和历史轮的 1～3 张截图均默认收起，每张图片可以独立展开和收起。
- [ ] 点击已显示图片可以收起；Tab、Enter、Space 和焦点轮廓可正常操作。
- [ ] 展开未缓存历史图只读取一次；收起与重展开不清空 `image.data` 或 `round.userScreenshot`。
- [ ] 加载中收起后，迟到成功响应只进入缓存，不自动重新展开或串到其他 Session/Record。
- [ ] 统一 system behavior 明确多图多题、跨图合并、重叠去重、题号映射、待核对与本轮答案汇总规则。
- [ ] 单题不机械重复汇总；OCR、纯翻译、秒杀和举一反三等场景保持其既有边界。
- [ ] Solver 仍只发起一次模型请求，全部截图按原顺序保存在同一条 user multipart 消息中。
- [ ] 前端、Prompt、Solver 专项回归和全量普通自动验证通过；Windows GUI 与真实模型效果单独标记人工验收状态。

## 非目标

- 不扩展一次请求最多三张截图的上限。
- 不新增 OCR 预处理、题目结构化解析器、答案后处理或第二次模型汇总调用。
- 不修改题库 schema、截图读取后端、Mobile 协议、Provider 参数、输出存储格式或 Wails API。
- 不处理默认 `DomainId` 旧 ID 一致性问题，不重构全部角色 Prompt。
- 不删除、覆盖或迁移已有题库记录、截图、导出或验证程序。
