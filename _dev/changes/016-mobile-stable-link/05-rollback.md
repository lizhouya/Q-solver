# 回滚预案 05

## 回滚策略

- 首选定向还原 Change 016 的业务代码、测试、bindings 与文档。
- 不使用 `git reset --hard`，不删除或覆盖题库、输出、截图、普通配置或历史构建。
- `mobile-state.0.enc` / `mobile-state.1.enc` 默认保留；旧版本会忽略，再次升级仍可读取。
- 只有用户明确要求放弃固定链接状态时，才另行确认是否删除专用状态；删除会导致下次生成新链接。

## 回滚触发条件

- 固定模式不能稳定复用或临时模式错误复用旧 Token。
- Reset 后旧 Token 仍能建立新请求或旧 SSE 继续接收业务帧。
- Clear 后旧内容可通过刷新、重连、旧帧或迟到任务恢复。
- 持久化失败导致运行态与磁盘状态分裂。
- Mobile 生命周期出现可复现死锁、阻断桌面主功能或删除非 Mobile 数据。
- Token/完整 URL 进入禁止的日志、Snapshot、普通 Config、文档或浏览器存储。

## 回滚后行为

回到 Change 016 前版本后，Mobile Token 恢复为每次完整进程启动随机生成；该行为必须在交付说明中明确。已经执行的页面内 Clear 无法在 Mobile 页面恢复，但桌面与题库数据未被删除。

## 2026-10-23 补充修复回滚边界

- 定向撤销 `clear_mobile_display` 默认值与加载迁移、shortcut service 事件、App 前端事件处理、共享 store 的 busy 门禁、TopBar watcher/层级和设置清单；不要删除其他快捷键或用户配置。
- 已由正常设置保存的 `clear_mobile_display` key 在旧版中只会被忽略；再次升级后仍可读取。回修加载时可能把占用默认 `67+160` 的旧 action 置为空，回滚时不得自动恢复为重复绑定；如用户确需旧动作，应在设置中录制一个不冲突的新组合。不得为了回滚删除或覆盖整个配置文件。
- 回滚到不识别该 action 的版本后，Windows Hook 不再触发清屏请求；状态面板鼠标入口按回滚版本原有能力工作。
- 已执行的同步端 Clear 无法从 Mobile 页面恢复其页面历史，但桌面答案、题库、截图、导出和模型上下文从未被删除。
- 验证 EXE 回滚只允许恢复明确指定的历史验证版；不得覆盖 `build/bin/Q-Solver.exe`、RC、API 修复版或同步修复版。
