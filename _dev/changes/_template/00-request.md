# 变更请求 — 00

> 本文件是每项二次开发变更的**第一份文档**，必须在**任何业务代码修改之前**创建并填写。

| 字段 | 值 |
|---|---|
| 变更编号 | `NNN-名称`（如 `001-hotkey-rebind`） |
| 提出人 | （姓名 / 角色） |
| 提出日期 | YYYY-MM-DD |
| 关联 Issue | （可选） |
| 状态 | `规划中` |

## 1. 背景与问题

> 客观描述当前遇到什么问题、为什么需要这项变更。可引用 `01-current-state` 中的现状作为佐证。

## 2. 目标

> 变更完成后要达到什么效果。必须是**可验证**的描述。

## 3. 验收标准

> 勾选即通过。尽量写得可测。

- [ ] 标准 1：例如「窗口隐藏时不再被录屏软件捕捉」
- [ ] 标准 2：例如「新增快捷键在设置页可见且可重绑定」

## 4. 非目标 / 明确不做

> 防止范围蔓延。例如：不改动官方源码结构、不引入新依赖、不调整 UI 主题等。
