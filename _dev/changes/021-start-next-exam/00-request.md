# Change 021 变更请求：开始下一套笔试

日期：2026-10-24
状态：规划完成，待实施。

## 1. 背景与问题

当前导出会封存当前分段，但桌面历史、待发送截图和模型上下文不会自动清理。下一次正式解题虽然会懒创建新分段，用户仍缺少一个明确、安全的“开始下一套”入口。前端导出提交成功只代表后台任务启动，`organizing` 结束也可能是成功、失败或取消，因此不能用导出状态下降沿自动清理。

## 2. 目标

- 在主解题区提供“开始下一套”按钮，并提供 Windows 默认快捷键 `Ctrl+Shift+N`。
- 按钮与快捷键只打开同一个确认层；确认后由后端原子校验并执行。
- 成功后清理桌面历史、待发送截图、流目标和 Solver 非 system 对话历史；下一次正式解题再懒创建新分段。
- 完整保留题库原始记录、归档截图、旧导出目录和 Mobile 当前显示。

## 3. 验收标准

- [ ] active/paused 当前段安全封存为 ended；ended/exported 幂等成功，discarded/空段拒绝。
- [ ] 解题、capture、整理、导出、未落盘或写阻塞期间拒绝，且全部状态保持不变。
- [ ] 确认成功后桌面历史、待发送截图、流状态和 Solver 上下文清空，`conversationEpoch` 只增加一次。
- [ ] 下一次正式提交才创建新 Session，不预建空分段。
- [ ] `Ctrl+Shift+N` 可重绑定；旧用户配置不会被默认值抢占。
- [ ] 快捷键仅发确认请求，取消和后端失败均无清理副作用。
- [ ] Mobile URL、Token、显示内容和 display epoch 均不改变。

## 4. 非目标

- 不从不可靠的异步导出状态自动触发切换。
- 不删除、覆盖或迁移题库记录、截图和旧导出。
- 不把当前段标记为 discarded，不新增第二套 Mobile 清屏协议。
- 不调用真实模型，不新增依赖，不升级 Wails runtime。

## 5. 影响面

涉及 Store 状态转换、App 原子命令、快捷键默认配置/录制、Vue 确认层与状态清理、Wails bindings、回归测试和中英文文档。主要风险是持久化失败后的半清理、锁顺序死锁、默认快捷键抢占和导出进行中误切换。

## 6. 授权边界

用户已授权实施本 Change；未授权 commit、push、Tag 或 Release。不得读取或输出 API Key、Mobile Token 和私人配置，不覆盖正式 `Q-Solver.exe` 或既有验证程序。
