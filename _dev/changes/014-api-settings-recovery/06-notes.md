# 总结与注意事项

API 配置加载与接入流程的已复现缺陷已修复，自动化通过。原有配置的检查仅报告 SET/NOT SET，开发过程未改写用户密钥文件。

- 密钥已保存不等同于服务商连通；不把运行状态文案当作真实 API 测试结果。
- 草稿请求必须携带地址和 Key，修改前端局部状态不能改变 Go 服务的已保存端点。
- 主配置读取必须独立于场景或题库；未成功加载不得保存默认空值。
- 题库和普通设置是两个持久化域；分别报告失败，不伪造全成功或事务性回滚。
- 新版加载/打开设置不自动请求模型列表；用户在模型页点击刷新后选择模型，显式点击测试可能产生服务商费用。
- 构建产物：build/bin/Q-Solver-api-fix.exe；旧 EXE 保留。程序有单实例锁，启动新版前应正常退出旧实例，而非仅隐藏窗口。
- race 被 Windows 0xc0000139 阻塞；GUI 与真实服务商为 NEEDS_USER。
- 当前仍在 dev/qsolver-custom，既有修改全部保留；未暂存、未 commit、未 push、未 Tag/Release。
