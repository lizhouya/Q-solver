## 1. 背景与问题

Q-Solver 当前只能在桌面 WebView2 窗口内查看 AI 解题结果（截图 → `Solver.Solve` → 事件 → `solution.js` 渲染）。在「真实考试/做题」场景下，用户希望**把解答结果显示到手机浏览器**，桌面可隐身（Ghost 模式）。

架构审计 002 已完成（`_dev/audits/002-mobile-output-design/`），确定了候选方向并整理出需产品决策清单（D-Mobile-001~006）。产品已逐条确认决策（见下文 §6），本次变更在此基础上进入**第一阶段实现**。

## 2. 目标

在 Q-Solver 中新增「**手机浏览器作为第二输出端**」能力，达成：

1. 启动一个**本地局域网 HTTP + SSE Server**（不对外网开放）。
2. 复用现有解题事件（不做第二套 LLM 逻辑），把 `solution` 事件镜像到手机端。
3. 提供**独立手机 Web 页面**（不侵入现有桌面 Vue），展示：等待状态 → 分析过程 → 答案。
4. 支持 **OutputMode**：`desktop` / `mobile` / `dual` 三态切换，默认 `desktop`。
5. 提供**二维码 + URL** 两种连接入口（二维码为主、IP 手工输入备用）。
6. 第一版手机端**只读**（不提供控制/反控）。

## 3. 验收标准

- [ ] 桌面端启动后，局域网内手机浏览器能通过二维码 / IP 地址连接本机 SSE 服务
- [ ] 手机连接后能实时收到：解题状态（waiting / streaming / done）、题目截图、简短分析、答案
- [ ] 桌面正常解题流程**完全不受影响**（桌面渲染仍照常）
- [ ] OutputMode 切换：`desktop`（默认）不影响桌面；`mobile`/`dual` 生效；切换开关在设置中可见
- [ ] 手机刷新 / 断开重连后能自动恢复（保留 SSE 自动重连）
- [ ] `go build ./...` 与 `npm run build` 均通过
- [ ] 关闭 Q-Solver 后 SSE 服务随之停止、端口释放、无残留进程

## 4. 非目标 / 明确不做

- ❌ 不修改 LLM Provider / Prompt / 截图 / 模型调用逻辑（F-001 等不在此范围内）。
- ❌ 不重构 `pkg/solution` 的 `Solve` 流程。
- ❌ 不升级第三方依赖（优先标准库 / 现有依赖）。
- ❌ 不实现公网访问/云中继。
- ❌ 第一版手机端**不提供反控**（停止/重新解题/切场景等均不做）。
- ❌ 不保存用户数据、不保存题目截图、不保存答案历史（内存态 + 连接时短暂持有）。

## 5. 影响面预估

- 涉及业务源码文件（预计）：
  - 新增 `pkg/mobile/`（SSE server + 事件桥）
  - 新增移动端 Web 页面资源（嵌入或独立静态）
  - `app/app.go` / `app/solve.go`（在解决方案事件出口处接入桥，最小侵入）
  - 前端增加 OutputMode 设置 + 二维码展示（小范围）
  - 可能触碰 `main.go`（embed / 启动顺序）——**仅在必要处**
- 需要同步更新的文档：`01-current-state.md`、`02-plan.md`、`03`~`06`、`INDEX.md`
- 潜在风险：
  - 新增局域网端口可能触发 Windows 防火墙提示
  - OutputMode 与现有 `solution.js` 事件流若衔接不当可能影响桌面渲染
