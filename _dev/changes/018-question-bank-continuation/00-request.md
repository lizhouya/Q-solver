# Change 018 请求

日期：2026-10-23
状态：方案已确认，进入实现；未提交、未推送、未发布。

## 用户请求

在“笔试题库”最近历史分段旁提供明确的“继续此分段”入口。成功进入后关闭题库弹窗，在截图解题主界面显示该段的历史截图和完整答案；下一次截图解题真正追加到该旧分段，并恢复其模型对话上下文，效果类似继续历史对话，而不是弹窗内伪浏览。

## 已确认决策

1. 采用真正续接旧分段，不只是视觉回放。
2. `ended`、`exported` 可续接；切换产生的 `paused` 可切回；`discarded` 永久只读。
3. 恢复历史非 system 消息，但下一次请求使用当前模型、场景、Prompt 和简历配置；旧 Model/Scene 仅展示。
4. 当前 active 段安全暂停后切换；正在解题、后台 goroutine 未退出、存在未发送截图、未落盘 Record、整理或导出时拒绝。

## 验收标准

- 目标历史段在主解题界面显示 1～3 张历史截图、完整答案、Record 状态和旧 Model/Scene。
- 新提交写入目标 Session；切回 paused 段后题库 current、主界面和 Solver 上下文同步。
- 旧数据明确标注“按题库记录重建上下文，可能与当时实际上下文不同”。
- Change 018 后的新记录持久化实际 retained turn 引用和 KeepContext 边界，重启后可恢复。
- exported 旧输出保留，再导出创建新后缀目录；discarded 无继续入口。
- 快速 A→B、取消和迟到流事件不串段；Change 016/017 行为不回退。

## GUI 验收回修：分段操作区布局

2026-10-23 的 Windows GUI 验收截图显示，不同分段因右侧存在 0、1 或 2 个操作按钮，导致左侧卡片宽度不一致；“继续此分段”和“重新导出…”横向占位也会挤压分段标题、时间与状态。

追加验收标准：

- 桌面端所有分段卡片保持一致的右边界，操作按钮使用固定宽度的独立操作列。
- 同时出现“继续此分段”和“重新导出…”时纵向等宽排列，不遮挡、不压缩卡片内容。
- 窄屏改为卡片在上、操作区在下的单列全宽布局，不产生横向滚动。
- 浏览、继续和重新导出仍是三个独立操作；按钮状态矩阵、禁用条件、键盘焦点和 `@click.stop` 语义不变。
