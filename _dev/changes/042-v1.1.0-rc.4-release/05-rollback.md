# 回滚预案 05

## 回滚策略

- [x] **发布前定向修正**：Tag 未推送时，以新提交修正文档，不改写既有 Change 040/041 提交。
- [x] **公开后前进修复**：Tag 已推送后保留不可变历史；使用后续 RC 修复，不移动或强制覆盖 Tag。
- [ ] **删除公开 Tag/Release**：不在当前授权范围内；只有用户针对具体对象再次明确确认后才可执行。

## 回滚触发条件

- rc.4 正文缺失、文件名与 workflow 不匹配或包含敏感信息。
- 分支、Tag、remote 或目标提交与审计不一致。
- 任一三平台构建/回归或 Create Release job 失败。
- Release 属性错误，或缺少平台附件/`SHA256SUMS`。
- 校验和未覆盖实际附件或附件元数据异常。

## 执行方式

### Tag 推送前

1. 停止发布操作。
2. 使用新的文档修正提交，不 amend 已有提交。
3. 重新执行 Git 预检、链接、diff 和提交边界验证。

### Tag 推送后

1. 保留失败 run、Tag 和 Release 的真实状态。
2. 不手工创建重复 Release，不删除或移动 Tag。
3. 记录失败日志，按新 Change 修复后发布下一 RC。
4. 如确需删除，先向用户列明具体 Tag/Release 和影响并重新取得授权。
