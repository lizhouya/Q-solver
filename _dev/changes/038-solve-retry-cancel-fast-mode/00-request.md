## 1. 背景与问题

网络波动、上游暂时不可用或流式连接中断时，当前错误卡片只能显示诊断，并提示再次使用截图快捷键；发送前截图缓冲已经被消费，用户必须重新截图。限时题中，长时间推理也缺少明确的中断入口；现有发送快捷键只能使用当前持久化场景，无法在不改设置的情况下临时切换为“秒杀技巧”。

## 2. 目标

1. 失败或用户中断后，可在错误卡片中手动重试，复用原始 1～3 张截图、同一轮显示目标和同一题库记录，不重新截图。
2. 增加“中断解题”按钮和可配置快捷键，真实取消当前 HTTP/SDK 流式请求；中断不是可续传暂停。
3. 增加“快速解题”快捷键，单次请求使用现有 `gen-speed` 场景，不修改用户保存的默认场景。
4. Desktop、Mobile、题库、KeepContext 与动态快捷键提示保持一致且可验证。

## 3. 验收标准

- [x] 网络错误、timeout、503、流中断和用户取消后，当前轮显示“重试本题”，重试不调用截图服务。
- [x] 只允许后端当前授权的失败轮次重试；任意旧轮次、成功轮次、过期会话和重复点击被安全拒绝。
- [x] 开启题库时，重试复用同一 Record，不新增重复题目；图片引用保持不变。
- [x] 重试前失败请求未写入 Solver KeepContext；重试成功只提交一轮 user/assistant 历史。
- [x] “中断解题”会取消 Provider context，旧任务完全退出前禁止普通发送、快速发送和重试。
- [x] 中断终态为 `cancelled`，Desktop 与 Mobile 显示“已中断”，不冒充网络错误；已流出的部分正文可见且标注可能不完整。
- [x] 普通发送使用当前持久化场景；快速发送只对本次请求使用 `gen-speed`，不修改 Config、不保存设置、不通知配置 subscriber。
- [x] 快速失败后的手动重试仍为快速模式；题库记录保存实际模型和场景。
- [x] Windows 默认快速/中断快捷键为 `Ctrl+Shift+J` / `Ctrl+Shift+X`，macOS 为 `⌘⇧J` / `⌘⇧X`；冲突时保持未绑定，不覆盖现有 action。
- [x] ScreenshotDock、Welcome、设置页和 Mobile 快捷键提示使用实际绑定；既有三图上限、FIFO、同步端 Reset 和清屏代际不回归。
- [x] 自动测试只使用 fake Provider 或 `httptest`；不读取真实配置、不调用真实收费 API。

以上由自动测试、保护候选验证及用户于 2026-11-11 对当前测试版本“没有什么问题”的确认共同验收；race 环境阻塞单独披露，不伪造为 PASS。用户随后明确要求更新本地版本，已将相同哈希候选晋升为根稳定版并完成旧版、验证版双归档；未创建 Tag 或 Release。

## 4. 非目标 / 明确不做

- 不自动重试、不实现指数退避或后台无限重试。
- 不支持从流式 token 断点继续；中断后只能重新发起请求。
- 不为快速模式增加第二套模型或 Connection Profile。
- 不增加 Mobile 远程重试/取消控制接口，不扩大局域网网络暴露。
- 不保证快速模式一定降低服务端排队或网络延迟，只保证使用简短场景并尽早输出答案。
- 不持久化无题库模式的重试图片，不承诺应用重启后仍可重试。
- 不修改三张截图上限、题库导出格式、Connection Profile schema、依赖版本或 Wails runtime。
- 不复用或改写现有未接入 UI 的 `InterruptThinking` 字段。
