# 实施方案 02

## 总体方案

在现有 Store v2 上增加“导出草稿 + 单次导出请求”，把长期偏好与单次选项分开。前端新增独立导出弹窗；后端负责校验字段、生成安全名称、按指定目标目录导出，并继续保证原始记录不可变、重复导出不覆盖。

## 一、后端数据与接口

1. 增加导出请求/草稿类型，字段覆盖：目标分段 ID、单位、题型、题库名称、本次目录、本次是否模型整理，以及名称是否由系统自动生成。
2. 提供当前段和历史段的导出草稿查询：读取已有 Session/Questions，本地建议单位、主导题型、名称和默认目录；不调用模型。
3. 增加带请求参数的当前段与历史段导出入口；保留或包装旧入口以降低兼容风险，前端统一调用新入口。
4. 一次性目录只作为最终导出的目标根；恢复记录仍保存在设置中的 `ArchiveDir/_记录`。所有路径和文件名由后端验证与净化。
5. 模型整理授权改为本次请求值；打开/取消弹窗不调用模型。历史重导出同样使用弹窗确认。
6. 单位为空时按分段日期和当日顺序生成 `笔试_YYYYMMDD_NN`；题型为空回退 `综合笔试`。用户填写的题库名称优先。

## 二、整理数据与 Markdown

1. 组织结果增加独立 `ReferenceAnswer` 字段，模型 Prompt 只从题目与原答案提炼，不确定时填“待核对”，禁止冒充官方答案。
2. 组织稿改为试卷模板：标题和元信息 → 分类后的连续编号试题 → 文末参考答案与解析。
3. 组织稿不输出任何截图或图片链接；`原始记录.md` 继续输出全部截图、原答案、状态和整理错误。
4. 关闭本次模型整理时只生成 `原始记录.md` 与 `assets/`，不生成误导性的空组织稿。
5. 开启整理时，组织稿文件名使用安全化后的题库名称（`<题库名称>.md`）；重导出仍通过新目录后缀避免覆盖。
6. 保持模型生成字段的 HTML/外链中和，保持原答案逐字不改写。

## 三、前端交互

1. 新增 `QuestionBankExportModal.vue`，支持当前段和历史段：
   - 显示导出范围和提交次数；
   - 可编辑单位、题型、题库名称；
   - 本次目录默认取设置值，可调用目录选择器临时修改；
   - 本次模型整理开关默认取设置值，并显示上传与费用提示；
   - 预览预计输出文件；取消无副作用。
2. ActionBar 的“导出题库”改为打开弹窗；新增“结束本段”，只在 Active/Paused 且无未保存数据时可用。
3. `QuestionBankPanel.vue` 移除重复目录卡和当前段主导出按钮；保留状态、结束本段、软清空、进度、最近结果和历史。历史“重试整理/导出”改为打开同一弹窗。
4. 顶部标签按状态显示“待记录 / 本段 N 次提交 / 整理中 / 上段已导出 / 上段已结束 / 上段已清空”。
5. 设置页移除长期单位输入，只保留默认目录和默认模型整理授权；偏好文件中的旧 company 字段继续兼容读取，不主动破坏旧配置。
6. 更新 `services/api.js` 和 Wails bindings/models；不新增 npm 依赖。

## 四、测试与验证

### Go 测试

- 导出草稿在有/无单位、有/无已有整理结果时的默认值。
- 无单位每日顺序编号稳定且不与现有导出冲突。
- 自定义目录只影响最终输出，不移动恢复记录。
- 用户命名文件、非法名称净化、重复导出后缀。
- 组织稿无图片语法，题目和答案分区、连续编号、参考答案字段。
- 未整理时只输出原始记录和 assets。
- 取消/部分失败仍保留原始记录与已有结果。
- 旧会话和旧偏好兼容。

- 执行前端生产构建，检查 Vue template/script 编译。
- 执行聚焦 Go 测试、全量 `go test ./...`、`go vet ./...`、`go build ./...`。
- 执行 Wails 生产构建并检查生成噪音；不升级项目 runtime。
- 执行 `git diff --check`。
